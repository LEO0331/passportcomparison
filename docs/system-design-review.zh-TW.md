# 護照比較工具架構

Flutter 應用程式部署在靜態網站。入境資料先在發布前匯入和驗證，再隨應用程式發布。網站首次載入需要存取已部署的程式及資產。應用程式載入資料後可在本機執行比較，無須連線至資料供應商。

## 資料流程

1. 匯入工具從可追溯的 TravelRequirements.info 版本讀取資料，驗證來源及正規化結果。應用程式只包含比較所需的資料及中繼資料。上游的完整稽核檔案及變更記錄保留在應用程式之外。
2. 資料層讀取內建資產，並轉成具型別的護照、目的地、入境規定及中繼資料。缺少單筆規定時顯示「未確認」。整份資料無法載入時，畫面會顯示資料無法使用。
3. 比較邏輯依據兩至五本不同護照產生摘要和目的地列表。摘要、篩選、詳細內容及 PDF 使用相同的入境分類。
4. SharedPreferences 儲存比較設定。既有收藏從原本的偏好設定讀取，開啟時依目前資料集驗證護照代碼。
5. 分享網址只包含護照代碼。應用程式讀取資料集後驗證代碼，並在 GitHub Pages 的既有路徑內還原選擇。
6. PDF 使用已載入的比較結果及資料集版本。完整報告列出所有納入比較的目的地，差異報告只列出入境類別不同的目的地。兩種報告皆標示未確認的規定。

入境類別、來源層級、授權和更新程序請參考[資料方法說明](data-methodology.md)。
